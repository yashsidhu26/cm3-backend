WHAT HAPPENS AUTOMATICALLY ON SIGN-IN
──────────────────────────────────────────────────────────────────────────────

When a user signs in via: POST /api/moodle/sign-in

Step 1: ✅ Authenticate with Moodle
  - Validates credentials
  - Gets Moodle token and user ID

Step 2: ✅ Create/Find Local User
  - Creates account if new user
  - Links BITS ID to account

Step 3: ✅ Store Encrypted Moodle Token
  - Securely stores token for future API calls

Step 4: ✅ AUTO-SYNC COURSES FROM MOODLE
  - Fetches all enrolled courses
  - Matches with BITS catalog (from all_courses.json)
  - Links handouts (from handouts.json)
  - Creates enrollments
  - Syncs course resources

Step 5: ✅ AUTO-SYNC SECTIONS FROM STUDYDECK
  - For ALL enrolled courses with staticId
  - Fetches section details (lecture, tutorial, lab)
  - Stores timings (day, start, end)
  - Updates room numbers and instructors
  - Ready for schedule generation

Step 6: ✅ Create User Session
  - Returns JWT token
  - User is signed in

ADMIN SETUP (ONE-TIME)
──────────────────────────────────────────────────────────────────────────────

Before users can sign in, admin must:

1. Seed BITS Course Catalog
   $ bun run seed:courses
   (Populates all_courses.json + handouts.json into database)

2. Set StudyDeck Token in .env
   STUDYDECK_JWT_TOKEN=your_token_here

3. Run Database Migration
   $ bun run db:migrate

That's it! System is ready for automated syncing.

TROUBLESHOOTING
──────────────────────────────────────────────────────────────────────────────

Q: Sections not syncing?
A: Check if STUDYDECK_JWT_TOKEN is set in .env

Q: Some courses have no sections?
A: Normal! Only courses with staticId can sync sections.
   Courses without staticId (custom/new) won't have StudyDeck data.

Q: Sync taking too long?
A: Large number of courses can take 10-20 seconds.
   Consider background job processing for production.

Q: StudyDeck token expired?
A: Update STUDYDECK_JWT_TOKEN in .env and restart server.
